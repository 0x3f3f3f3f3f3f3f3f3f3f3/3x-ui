# Canonical global and node client mapping design

Typed authority transport closed with its sole review and author correction pass; normal feature publication independently verified exact SHA f558d98019d6a0f16ba52ec77c7e81d6b87e3ed1. This binding design governs the following implementation. Original priorities remain Snell/mieru/SSH, multiplier billing, directional limits and TCP/UDP Tunnel; original full project remains open.

Original requirements section12 explicitly distinguishes global and node scopes, rejects giving every node full global quota/rates, requires bounded outage behavior and forbids applying multiplier again to aggregated node reports. Current production grant payloads use the execution node's local stable client UUID. A coordinator account must use a canonical global UUID. Existing Remote.AddClient returns no stable resource identity; email/credential/protocol UUID cannot substitute for trusted local client identity.

The next boundary must prove immutable global↔local stable UUID mapping bound to the actual source and delegated authority/node tuple, before a grant can translate IDs. Keep existing remote-policy scope guards until global/node model/API/UI, the coordinator factory and actual two-node allocations all pass. Mapping alone is not the global-policy product.

Use a strict typed authenticated TLS operation in the existing32KiB owner-admission chain. Input has the same expected source/boot/coordinator/node binding and explicit canonical global/local client UUIDs. Read the current local SQL record and actual private-core policy under retained owner/current database admission; tombstoned/missing/foreign/changed/consumed clients refuse the initial fresh enrollment. No request can alter stable resource identity or credentials. Response proves both UUIDs, current binding, policy version and zero enrollment usage; never infer identity from email alone. Consider enrollment retry after a consumed grant separately from initial enrollment: an already committed identical mapping should remain discoverable rather than being silently replaced.

Pin immutable mappings in the node's original independent journal evidence as well as a SQL projection; ordinary SQL import/restore must not manufacture, retarget or erase enrollment. Audit journal schema/old-writer rules before adding mutable evidence. Record the coordinator's mapping in a dedicated table, exact source/node/authority tuple, independent role binding and stable peer configuration. An old boot requires fresh discovery/registration; a different source or role requires an explicit handoff, never silent rebinding.

A mapped authorityDemandAPI wrapper translates only cloned client-ID fields between canonical journal UUID and pinned local core UUID. Translate demand, grant installation/state, get/pause/seal and renewal consistently in both directions. Preserve grant/window/sequence/challenge/capacity/shares and exact cumulative billed/remainder values; never multiply reports. Unknown mappings fail closed. Design demand filtering so unknown local clients cannot permanently starve mapped clients in a bounded page. In-flight mapping deletion/replacement must not turn an acknowledgement into another account's usage.

Policy versions are also node-local monotonic identities. A canonical global version cannot be assumed equal to each node's version after policy edits. Initial mapping requires an explicitly pinned canonical/local version pair and the same effective policy fingerprint (multiplier, quota, expiry and directional limits); mapping ID fields alone is insufficient. The mapped adapter translates the proven version pair and rejects any unplanned effective-policy change. A later policy update must commit a new effective-policy proof under retained node admission before granting its canonical version. This prerequisite does not certify hot updates or global-scope UI completion by testing only initial equal-version enrollment.

The original journal currently creates schema4, upgrades to schema5 for reset capture, and already uses schema6 for reset-operation progress. Mapping evidence therefore needs schema7 compatibility fencing rather than adding fields that schema4/5/6 writers could silently discard. Retain both existing writer fixtures, add a frozen current-schema6 mapping refusal probe and test readonly reopening/migration as well as subsequent writes. New mapping-only journals need not invent reset-progress records; bucket presence must preserve whether reset progress actually exists. Durable mappings are immutable, bounded, owned by the committed journal execution role and validated on reopen; a disposable SQL projection cannot establish their authenticity.

Required actual evidence: distinct canonical and local UUIDs through the real production TLS mapping/controls and independently journal-issued grant; literal TCP/UDP2x bytes charged once to the canonical account; malformed/duplicate/alias/type/limit failures; complete local-owner/restore/busy/socket/oldboot refusals; forged/changed mapping rejected by original evidence; deletion/retry/reopen/SQL restore keep identity and uncertain allocation. Both SQLite/PostgreSQL exact no-skip gates, native5 and current full source/core provenance remain required.

Following product must expose explicit node/global scopes in model/API/UI and coordinator ownership, including allocation/reconciliation over at least two actual node processes. Global scope uses one canonical account with nonoverlapping quota/rate/burst shares; node scope uses separate per-node accounts with unambiguous UI accounting. Scope migration of consumed local sources requires an explicit sealed report/handoff and original-anchor semantics. Do not implement a full-quota-per-node approximation while claiming global enforcement.
