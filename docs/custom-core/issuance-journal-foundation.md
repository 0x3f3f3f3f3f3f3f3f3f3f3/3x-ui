# Issuance journal foundation

This is the Task 3 control-plane primitive under [restore-authority-lifecycle-plan.md](restore-authority-lifecycle-plan.md). It is not yet used to authorize business listeners. Existing managed remote-scope guards remain in force.

`internal/policyauthority` explicitly creates or opens one private synchronous bbolt journal outside imported SQL and node execution state. Creation refuses an existing file; opening refuses missing, wrong-identity, shared-permission or contradictory state. Initial seeds remain immutable. Confirmed raw/billed history, initial and per-grant fractions, current window use, uncertain frozen allowance, outstanding finite capacity and directional rate/burst sums survive reopen. Opening recomputes cumulative history and held allocation sums from the complete records.

Issuance binds authority identity/generation, node/source/fresh boot, canonical client, window/version and request/challenge. A transaction commits the finite allocation before returning it. Exact request retries reuse the committed grant; changed intent is rejected. Limited zero directional shares are distinct from explicit unlimited mode. Independently issued capacity and limited rate/burst sums cannot exceed their policy bounds. Reported billed consumption is accumulated directly, without applying a multiplier again. Cumulative reports reject regression, conflicting sequence reuse and capacity excess.

A current-incarnation seal releases only verified unused capacity and its shares. Node reboot, expiry, lost control, deletion or an unconfirmed report releases nothing. Retired boot identities are durably recorded and cannot be reactivated by delayed registration. Deleted canonical identities retain terminal tombstones and old allocation/history. Exact provisioning retries preserve the original seed and current confirmed totals.

Schema 2 adds immutable policy/window transition records and a per-account revision. Exact change/reset retries preserve the first captured boundary, including after reopen and later reports. Reset deliberately credits confirmed period usage and initial frozen uncertainty, while retaining outstanding grants and lifetime evidence. Late reports after the boundary enter the current window. Policy decreases retain old quota/rate/burst holds; an old unlimited directional grant also blocks new limited allocation until sealed. A prior window identifier cannot be reused. Historical grants remain tied to their original policy.

Confirmed and held billed quantities use whole bytes plus millionths, with exact carry/borrow across grants, resets and reopen. Settlement never applies the multiplier again. Fractional usage cannot regress or exceed its finite grant, and sealing cannot round remaining capacity up. Every committed effect advances a signed-SQL-compatible revision once; retries do not. Opening recomputes revisions, policy history, cumulative fractions and remaining capacity. Earlier schema-1 development journals are rejected and retained for explicit reconciliation; missing history is never silently initialized.

The conservative allocator currently retains uncertain rate shares indefinitely until a valid seal; this trades availability for exclusion. `MaxLeaseDuration` is 10 seconds, but this primitive does not implement execution deadlines or grant renewal. The core must bind installation to a challenge born on its monotonic clock before issuance. Replayed installation must not restart a deadline, allowance or limiter. These execution requirements remain Task 4 work.

The journal assumes one active control authority. Its file lock excludes a second open of the same file; it cannot exclude a simultaneously operated copy of the whole authority or prevent authority-state rollback. Those cases require an external fencing source. Copied node SQL/execution snapshots must be fenced by fresh core incarnations and this unchanged authority; that integration remains open.

Twenty-five top-level journal race tests passed in `restore-authority-journal-projection-precommit.jsonl` (1.925 seconds); package vet and diff checks passed. They include the opening, issuance, settlement and tombstone regressions, durable transition/retry boundaries, lowered limits, unlimited-to-limited exclusion, initial uncertainty reset, exact fractional carry and SQL-limit transaction rollback. Deleted identities reject even exact replay of previously issued unsealed grants. Opening also refuses to recreate a file that disappears after the initial path check, and enforces the journal size limit through bbolt's open options. These tests prove the journal's bounds, not encrypted protocol payload or coordinated node enforcement.

`client_policy_authority_projections` stores the canonical identity, authority identity/generation, revision and exact account snapshot. The private service adapter joins the existing serialized SQL transaction and restore lease/generation checks before calling the journal. Contradictory identity, future revision or same-revision payload fails before issuance. Journal issuance commits before projection; SQL failure exposes no grant and retains the original durable allocation for retry. A valid older projection can be rebuilt from the journal. Terminal deletion also restores the SQL tombstone without erasing final usage.

Six SQLite authority integration parents passed under race (5.192 seconds), including actual online-backup/reopen of an older SQL snapshot with the journal retained. Five PostgreSQL projection parents passed under race in isolated schemas (14.090 seconds); this gate does not claim a PostgreSQL dump/restore. Seventeen combined authority/writer/lifecycle parents passed under race (9.245 seconds). The adapter is a control-plane prerequisite; managed process activation and ordinary accounting views have not yet switched to it.

Remaining integration includes initial drained SQL/core migration, activation and settlement calls into the projection adapter, runtime policy/reset cutover, commit/crash fault acceptance, configured private authority identity, boot-bound core grants/renewal/sealing, authenticated node requests and product scope controls. The configured copied-core regression remains failing until that execution path is implemented.
