# Managed global and node policy product design

This is the next original section12 product, following the independently published mapping correction7320f366. Snell, mieru, SSH, exact multiplier billing, directional limits and TCP/UDP Tunnel remain the primary data paths. This specification does not claim implementation or acceptance.

The public client policy declares `scope: node|global`. Missing scope preserves existing node behavior. Global means all enrolled nodes share one canonical quota and bounded upload/download rate and burst allowance. Node means each node has an independent account and quota. The UI explicitly identifies both choices and displays global balances separately from each node's original-source usage. No scope change may erase old consumption or silently issue a new allowance.

Persist node accounts separately from the parent client record. A global client uses its existing stable canonical UUID. A node-scoped account has a separately persisted canonical UUID, parent client UUID and immutable enrolled node/source key; it never appears as a duplicate ordinary client. Both account types use full effective policy fingerprints, monotonic desired versions, existing reset boundaries and decimal-string accounting. Imported SQL projections cannot create allocation authority. New models join both schema and cross-database migration registries; exports preserve them.

The coordinator owns one independently anchored original journal and disposable SQL account/projection state. Open it under retained database/lifecycle admission and private directory validation; journal replacement, source mismatch and SQL restore never initialize an empty budget automatically. A managed controller is pinned to actual TLS discovery, delegated role, source, boot and immutable mappings. A restart re-discovers the same source and role; old allocations stay held until an actual seal settles them. Node-local and global accounts can coexist in one delegated core because all receive explicit coordinator grants, with distinct canonical account identities.

The existing controller currently requests the full direction allowance and up to2MiB quota, which is correct for its local issuer but unsuitable for simultaneous global nodes. Add an explicit allocation strategy for managed nodes. Stable sorted enrolled members receive nonoverlapping integer rate and burst shares, including remainder assignment; zero shares deny that direction. For each limited direction, the number of nonzero seats cannot exceed min(member count, rate, burst); distribute the entire finite rate/burst across those seats, with all other seats receiving rate0/burst0 together. This keeps even rate1 across two members valid and bounded. A lost response preserves its request/allocation. Retiring members retain held shares until actual seal; a partition cannot transfer their allowance. Document fixed-share utilization cost and do not promise instantaneous global rate rebalancing.

Bound each new quota request by the smaller of the immediately unallocated journal allowance, the2MiB request cap and the member's target slice of the total remaining window allowance. Compute the target before subtracting other members' held slices, so sequential first grants do not geometrically shrink128 into64 then32: both members can receive64 when none is consumed. Journal issue remains the final atomic conservation check. A node-scoped canonical account has one eligible member and independent quota; its allowance is never shared with another node account. Test tiny/fractional remaining allowances and simultaneous last-byte contention explicitly.

Production controller operations remain context bounded and journal first. They use mapped canonical IDs/versions and preserve all raw/billed/fraction counters. SQL reporting records cumulative source/grant receipts and journal projections without multiplying again; raw and billed coordinator totals already include the journal's original seed, not an extra legacy sum. Per-node displays preserve the grant's original node/source/boot and cumulative sequence. Unknown or unproven sources receive no grants. Changing a policy requires a separately committed version proof under both original anchors; consuming an old local issuer requires a sealed handoff with exact raw/fraction/reset history and durable acknowledgement. These are required subsequent tasks before ordinary consumed clients can be migrated.

Expose authenticated coordinator status, enrollment and policy/account API contracts through existing inventory, node-sync, TLS/token/CSRF and code generation. The client form offers scope and existing multiplier/directional limits; account display shows pending enrollment, outstanding held allowance and the actual remaining balance. Product flows explain decisions in user terms, without exposing journal implementation choices.

The actual two-node owner must use two separate processes, each with its own SQL database, runtime manager, original node journal, real Custom Xray process and production TLS controller routes. A test helper subprocess may reuse the existing native HTTP harness, but cannot share the process-wide database or manager. The parent coordinator owns a third SQL context and an independent journal. Private ephemeral fixture credentials are passed in0600 files and never printed. Assert distinct source/boot/node/local UUIDs and canonical/local versions.

Acceptance measures real simultaneous TCP/UDP through both nodes, global quota exhaustion, shared directional rate/burst bounds, node-scope independence, actual multiplier and fractional settlement, duplicate/out-of-order receipts, partition/lease expiry, coordinator outage, restart, deletion and restore. Extend actual Snell/mieru/SSH to the managed policy flow. Both SQL backends, exact literal parents with zero skips, fresh source/binary hashes, full Go/vet/frontend/generation equality and normal feature publication are required. Remaining original handoff/version/reset, sidecar migration, distribution/platform/scale/external client and final A–H acceptance continue after this product slice.
