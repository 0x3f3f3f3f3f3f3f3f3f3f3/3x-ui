# Durable delegated node mode decisions

The binding specification is [delegated-node-mode-design.md](delegated-node-mode-design.md); execution follows [delegated-node-mode-plan.md](delegated-node-mode-plan.md). The full original project remains authorized and required.

| Decision | Reason | Cost or remaining requirement |
| --- | --- | --- |
| Continue inline without renewed design/push permission menus. | Original autonomous engineering and specified feature-branch publication authorization persist. | No force push, default merge, release or deployment; exact remote SHA still required. |
| Retain the existing isolated worktree and every plan/evidence directory. | Preserve reviewable commits, failed attempts and interrupted-publication fixtures. | Additional disk usage; maintenance only removes independently audited old compiler archives. |
| Extend the independent authority manifest to schema2. | Source, identity, snapshot and execution role must form one durable record outside SQL/core restore. | Schema1 stays legacy local; missing/corrupt schema2 refuses rather than selecting local mode. |
| Pin role in original journal migration evidence. | A valid-value manifest edit or schema downgrade must not change issuer. | Register the exact new migration kind; old readers must refuse unsupported new evidence. |
| Resume only the identical preparing role and original snapshot. | Lost publication replies must recover without inventing another identity. | Changes after interruption safely refuse and require the exact prepared evidence. |
| Fresh stopped source only. | Consumed usage or active local authority cannot transfer ownership implicitly. | Existing local sources require a future explicit handoff; no migration shortcut. |
| Parameterize historical usage only in the existing test fixture. | New delegation requires0/0 while old local tests depend on100/200. | The old default remains literal; no consumed-local migration acceptance is claimed. |
| Allow absent local controller only for the exact journal-pinned delegated owner. | The core still needs proof of current process/source/socket/boot and initialized policies. | No local fallback; remote transport must supply future grants. |
| Reuse the retained journal on a live identical setup retry. | Reopening its bbolt file blocks while the owner holds it. | Revalidate lifecycle, SQL admission, source, role and owned socket; return copied values. |
| Delegated checkpoint only validates ownership. | It cannot issue or renew a local allocation. | Remote grant accounting/settlement remains follow-up work. |
| Reject delegated local reset at shared capture/execution admission. | Absent-controller RPC rejection was too late and interrupted the owner. | No reset backlog or SQL window write; coordinated reset transport is still required. |
| Make strict authority envelopes exact, unique and non-null. | Duplicate or case-alias fields could turn an ambiguous response into success. | Ordinary remote envelope paths retain previous behavior; invalid authority responses fail safely. |
| Correct browser Cookie fixture to its last saved value. | Login and CSRF each saved the same cookie; sending both replayed the original. | No production CSRF relaxation; valid and missing-token cases rerun. |
| Require fresh empty-source setup success in HTTP tests. | A stopped fresh source can be created without first running business listeners. | Test stable identity/exact role instead of an incorrect service-unavailable assumption. |
| Explicitly declare OpenAPI response schemas. | Response examples do not generate object field definitions. | Keep request/result/local/delegated role definitions and generated artifacts synchronized. |
| Record integration PASS as characterization. | Completed prior tasks already supplied correct end-to-end behavior. | No invented RED or extra production change; actual backend/core gates remain mandatory. |
| Freeze31 current inputs and actual core SHA. | Tests must refer to a reviewable source snapshot. | Any later code correction requires a new preserved snapshot and corresponding fresh acceptance. |

One sole fresh phase review follows all task contracts. Every finding and every item declined by that reviewer will receive an explicit author ruling here. Critical/Important corrections receive one author pass with meaningful RED→GREEN and final verification. Review and publication are pending; this phase provides durable delegated ownership, while typed remote grants, global/node policies, quota/rate partitions, actual two-node outage/recovery and remaining full-parent requirements continue afterward.
