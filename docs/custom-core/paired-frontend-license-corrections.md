# Frontend source and notice closure

The earlier clean `a980ef95012e34de12511e2fd807f5e6363f4392` package embedded React 19.3.0 without its complete MIT notice. The notice was absent from `licenses/`, the Git corresponding-source archive, and generated JavaScript. The Go compiled-dependency collector could not cover npm dependencies. The original package and its proof remain unchanged.

Every normal `npm run build` now creates `build/frontend-licenses/` separately from `internal/web/dist/`. The Vite plugin selects actual chunk modules, CSS/asset build inputs, and the Vite and Rolldown sources that supply emitted virtual runtime helpers. It does not collect the entire development dependency tree. For each selected npm installation path it retains the exact published `.tgz` identified by `package-lock.json`, checks the original SRI, and compares installed package metadata, compiled inputs and notice bytes against that archive. It uses npm's cached content when available; a missing cached archive can be fetched only from its exact locked HTTPS URL. Validation and package assembly require no network access after collection.

`frontend-compiled-deps.json` records package names and exact versions, installation paths, original lock integrity and resolved URLs, archive SHA-256 values, compiled input hashes, notice paths and hashes, frontend output hashes, and first-party build input hashes. All paths are relative. It contains no source-revision claim or local cache paths. Full notice files are copied unchanged from their locked archives, including notices published inside README files. First-party source remains in the existing Git corresponding-source archive; selected third-party sources are retained in their original npm archives.

Three locked packages require separately identified standard license terms:

| Package | Published attribution | Added terms |
| --- | --- | --- |
| `toggle-selection@1.0.6` | Exact `package.json` author, contributors and MIT declaration; its npm archive publishes no notice file | MIT, `declared-license-template` |
| `format@0.2.2` | Original complete `Readme.md` copyright statement and MIT link, plus the exact legacy `package.json` `licenses` declaration | MIT, `published-with-declared-license-template` |
| `short-unique-id@5.3.2` | Original complete README copyright statement and Apache 2.0 link, plus the exact package metadata | Apache 2.0, `published-with-declared-license-template` |

The MIT permission and warranty terms come from the [SPDX MIT text](https://spdx.org/licenses/MIT.html). The Apache terms are the complete [Apache Software Foundation license text](https://www.apache.org/licenses/LICENSE-2.0.txt), including its appendix. Generated supplements retain the exact original package metadata and point to the canonical text source; published README attribution is retained separately. They do not infer copyright years or holders. Only exact MIT or Apache-2.0 declarations, including a single legacy `licenses` entry, can receive this supplement. Missing or unsupported declarations fail collection. The `is-mobile` README already includes its complete MIT notice and stays unmodified.

For `toggle-selection`, public metadata for [the exact npm version](https://registry.npmjs.org/toggle-selection/1.0.6) identifies upstream commit `466460c75ca40630d8de940490718247fce79a3e`. The [source tree at that commit](https://github.com/sudodoki/toggle-selection/tree/466460c75ca40630d8de940490718247fce79a3e) also has no license file, and its `index.js` matches the locked installed file. The preserved registry response and tree listing document this absence; they are engineering evidence rather than a replacement source archive.

The native `tools/frontenddepsverify` command checks the complete regular-file sets, lockfile identity, archive SRI, archive package metadata, original and supplemental notices, first-party source inputs, virtual runtime provenance and every emitted frontend output. It rejects links, unsafe paths, missing files, undeclared files and mismatched bytes. It never invokes npm or downloads dependencies. Individual compressed npm archives are bounded at 128 MiB and their decompression at 256 MiB; closure and asset walks retain the 2 GiB bound. The existing paired-package 512 MiB compressed/2 GiB extracted limits are unchanged.

Linux assembly runs the verifier and copies the closure to `licenses/frontend/` before generating the package manifest. Prebuilt assets require both `PAIRED_FRONTEND_DIR` and `PAIRED_FRONTEND_LICENSE_DIR`, with `PAIRED_NODE_VERSION=v26.10.0`. Docker's native Node stage exports both directories to the target Go stage; the target stage needs no Node executable. The Windows workflow verifies and copies the same closure before its existing compiled Go dependency collection and ZIP hashing. Existing publication conditions are unchanged.

Engineering validation used Node 26.10.0 and Go 1.27.1. The actual Vite closure contains 182 selected packages, 399 regular files, 165 frontend outputs and 818 first-party build inputs. Its files total 32,346,780 bytes, including 30,485,792 bytes of compressed npm archives (181,168,640 bytes of uncompressed tar data). React's complete notice matches the installed and archived original with SHA-256 `da6d3703ed11cbe42bd212c725957c98da23cbff1998c05fa4b3d976d1a58e93`. These are component sizes; final clean package/image acceptance still measures the combined package.

Preserved evidence is in `build/frontend-license-correction-evidence/`: the original missing-notice failure, initial collection failures, npm installation/build logs, exact upstream absence evidence, collector and native verifier test logs, final closure size/hash proof, and actual-closure tampering proof. The tests exercise exact React notice/source collection; changed installed source, notice, SRI archive and version; unsafe paths and links; omitted or rewritten notices; rewritten archives even after updating their SHA-256 metadata; mismatched frontend assets and first-party inputs; and supported/unsupported declaration supplements. Fresh temporary test directories are retained for inspection. These checks establish the source-and-notice packaging behavior and do not make a blanket legal-compliance claim.
