# Durable delegated node execution mode

Original objective: real Snell/mieru/SSH first, then shared multiplier billing, directional rates and TCP/UDP Tunnel; complete the original project. Authenticated discovery alone does not allow coordinated grants because managed startup always creates a local authority controller. This checkpoint creates an explicit execution role that a later typed grant transport and global/node coordinator consume. It does not remove remote-policy guards or claim global execution.

## Choice and constraints

Retain the existing protected local control socket and one owned core. Choose a durable external role binding rather than a mutable SQL setting or a remote replacement of the local issuance journal. SQL restore must not turn a delegated node into a local allowance issuer. Keep the existing journal for protected policy/accounting evidence; delegated startup never starts its local allocation controller. Roles are explicit local or delegated. Delegated role pins the stable execution source and coordinator authority ID/generation/node ID. Ordinary configuration restore cannot change that tuple.

Provision delegation only on a stopped, fresh execution source that has never activated or accumulated usage. Any activated local source, existing authority journal, legacy traffic/final drain or mismatch refuses. A consumed local source needs an explicit future handoff, never automatic reassignment. A source identity already persisted before interrupted creation is reused. Once the private role record is published, an identical request is idempotent; changed binding is refused. Interrupted setup must retain the same binding or stay stopped.

Extend the existing independent authority manifest to schema2 with an immutable execution role/binding; reuse its create-only preparing→committed publication and source/snapshot digest checks. This is outside SQL/core snapshots and does not require a second parallel identity file. A schema2 manifest requires its explicit role; a schema1 manifest remains legacy local. Wrong/missing role evidence, permissions, symlinks or ambiguous JSON refuse, rather than reconstructing delegated mode as local. New local initialization records an explicit local role. The local identity/journal remains protected evidence and is distinct from the delegated coordinator binding.

## Startup and owned API

Delegated bootstrap still validates current source/config/policies, prepares business credentials and immutable historical initialization. Before business listeners start, bind the core to the pinned coordinator tuple and enable its existing on-demand request queue. Do not construct/start a local authorityController. Business admission remains denied or waiting until a boot-bound coordinator grant exists. There is no full-quota fallback and no autonomous grant renewal. Stop/restart closes only the retained owned API/core; a replacement boot starts with no usable predecessor grants and the same durable role.

Discovery continues validating the owned process/socket/source/boot and restore admission; it returns executionRole plus the pinned authority tuple for delegated nodes. Empty legacy role metadata means local for compatibility. A delegated response must carry the valid tuple. General startup-owner checking recognizes either a valid local controller or the exact durable delegated binding, never an arbitrary missing controller.

Expose POST /panel/api/server/clientPolicyDelegation through the same authenticated actual-TLS32KiB/CSRF chain. Strict object fields authorityId, generation, nodeId; generation1..MaxInt64 and ID bounds match core binding validation. Only admin/node-sync can configure; monitor remains denied. Response returns source identity and role binding without paths/secrets. Verified direct HTTPS Remote.ConfigureDelegation applies the same envelope/redirect/size limits. This performs setup only, not arbitrary core RPC.
