# Client mapping phase decisions

The original requirements remain Snell, mieru and SSH first, followed by exact multiplier billing, directional limits and Xray Tunnel TCP/UDP forwarding. This phase proves canonical/local identity translation over the existing protected node transport. It leaves the existing remote allocation guards in force until managed coordinator ownership and the actual two-node product pass.

| Decision | Reason and consequence | Following work |
| --- | --- | --- |
| Bind only an actually fresh node policy initially | Existing raw, fractional, frozen, reset or sealed-grant history cannot be erased by a new UUID. If a consumed node cannot join immediately, the cost is delayed enrollment rather than unaccounted historical usage. | Implement an acknowledged sealed handoff for consumed sources. |
| Keep original coordinator and node journals authoritative | SQL mapping rows are disposable projections. An imported or forged row cannot retarget either original journal. Losing an original journal requires explicit recovery; SQL alone cannot reconstruct allocation authority. | Test source clone, journal/core replacement and multi-source historical handoff. |
| Mapping versions are immutable | Canonical7/local1 is proven against the full effective policy. Changing either version invalidates execution through this mapping. The cost is refusing a legitimate update until a new version proof workflow exists. | Add version proofs under both original journal anchors. |
| Preserve uncertain capacity across node restart | A new boot does not prove that an old allocation was unused. The cost is held capacity until a genuine final seal is recovered. | Managed coordinator reconnect, expiry, partition and durable reset acknowledgements. |
| Validate canonical SQL before and after the peer RPC | SQLite immediate writer transactions cannot span the peer's own SQL proof. A concurrent change may leave a committed node proof with no coordinator acknowledgement; exact retry must recover it. | Keep both short transactions and journal-first projection order. |
| Historical core is a full pinned ancestor build | Missing history capability refusal uses the real earlier private core, including its local Snell dependency. Retained source archives and checksums cost disk space and build time. | Paired install/upgrade/rollback acceptance remains separate. |
| SQL projection restoration is tested separately from authority restoration | Dropping and rebuilding the table verifies recovery from the original journal. Cross-database export tests verify exact projection bytes. Neither is a claim that replacing the authority journal is safe. | Continue original backup/restore and original-anchor fencing work. |
| Exact2x business flow and fractional wire preservation have separate evidence | Actual TCP8/UDP8 produces raw16/16 and billed64 once. Synthetic adapter fractions prove byte-preserving translation, not real fractional settlement across two nodes. | Actual multi-node fractional business settlement and aggregate directional shares. |

One fresh review covers all four mapping tasks after their owning gates complete. The earlier typed-transport review is closed. Native protocol, official external Snell interoperability, remaining sidecar migration, full exports/notifications, platform distribution, scale/performance and the original final acceptance remain open requirements; this phase does not mark the full project complete.
