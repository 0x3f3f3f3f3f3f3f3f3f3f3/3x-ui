# Protected original inbound reset stamps

The user requires native Snell/mieru/SSH followed by multiplier billing, directional limits and TCP/UDP Tunnel forwarding. Current real-core acceptance covers these local paths. Complete restore authority remains required. This architectural increment integrates the persisted inbound UUID into the existing reset operation journal, starting with manual managed-client inbound resets and their inbound reset timestamp.

New manual inbound captures use a strict schema2 carrying sorted original inbound numeric IDs and canonical nonzero UUIDs; schema1 histories retain their existing compatibility. The selected resources are captured in the same pinned SQL transaction as original client membership, with a100000 resource ceiling. Capture of inbound:-1 fixes the original set; adding another resource later cannot expand it. Schema2 is restricted to manual inbound scopes and has no scheduled inbound counter effects.

For an operation whose original targets are all managed, update the reset timestamp only for captured UUIDs still present. A numeric ID, tag, port, credential or attachment match cannot transfer the effect to a replacement. Use the original execution ResetAt for this stamp. Serialize exact applied UUID/timestamp effects in a strict schema2 preparation before SQL commit; complete only after actual core application. Schema1 preparations remain unchanged. Unsupported legacy/calendar/remote effects retain their existing fail-closed recovery guards and receive no false execution acknowledgement.

Cold recovery projects the protected original timestamp by UUID, raising an older timestamp to the original protected value and preserving a later timestamp. Deleted UUIDs are omitted. Projection does not change inbound counters, enabled state, credentials, settings, tags, ports or attachments, and does not fund or acknowledge journal accounts/grants. Repeated metadata recovery is idempotent. Pure capture without preparation remains intent; ordinary retry executes the original set, rather than reselecting current numeric IDs. Durable preparation validation binds identity/source/request/capture digest, managed reset rows, original resource membership, unique sorted effects and exact execution time. Malformed and contradictory programs refuse.
